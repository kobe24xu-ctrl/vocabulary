# Cloudflare 免费试用部署

本项目可用 Cloudflare Workers 托管网页和 API，用 D1 保存班级、账号、成绩和错题。学生只需浏览器。运行时不依赖外部字体、CDN、翻译 API 或云端朗读服务。

**部署成功不代表中国大陆网络一定可用。** `workers.dev` 在大陆可能不稳定或无法连接，必须在学校网络和学生实际网络中关闭 VPN 试用。绑定自己的域名后也要实测；正式课堂若需要可预测的大陆连接，可采用 [国内服务器方案](mainland-deployment.md)。

## 账户授权

在任务的云环境设置填写：

- 环境变量 `CLOUDFLARE_ACCOUNT_ID`：Cloudflare 账户 ID（32 位字符，不是邮箱）。
- 网络密钥 `CLOUDFLARE_API_TOKEN`：只允许发送到 `api.cloudflare.com`。使用限定当前账户的自定义 API Token，授予 Account → Workers Scripts → Edit 和 Account → D1 → Edit。
- 网络放行 `api.cloudflare.com`、`developers.cloudflare.com`、`*.workers.dev`。

不要在聊天、仓库、命令行参数或日志中粘贴 Token、密码和学习码。不需要 Global API Key。

配置须保存并加载到运行环境。设置页面显示密文不代表当前任务已经加载；检查配置项状态，再执行实际 API 操作。不要打印变量值。

## 发布

开发环境需要 Node.js 24+、Python 3 和 `npm ci`。Cloudflare 运行时不需要安装 Python 或 Node 服务。

```sh
npm run cf:deploy
```

脚本使用现有 HTTPS 代理和环境授权，验证令牌，查找已启用的 `workers.dev` 子域名，创建本应用的新 D1 数据库，执行迁移并发布。初次部署遇到同名资源时使用新名称，保留原有资源。不启用付费方案，不修改域名 DNS。

生成的 `cloudflare/wrangler.deploy.json` 保存应用名、账户 ID 和数据库 ID，不含 Token，已被 Git 忽略。保留这个文件，后续部署会复用对应数据库。更换机器时从自己的 Cloudflare 控制台恢复正确的资源 ID；不要删除已有数据库后重新部署。共享模板 `cloudflare/wrangler.jsonc` 使用占位数据库 ID，仅供本地开发。

重新部署同样执行 `npm run cf:deploy`。D1 迁移有执行记录，不会重建学生和成绩表。

## 先试用界面

默认 `ALLOW_DEMO=true`。打开部署地址，点击「体验教师与学生演示 →」。每次进入会创建独立的虚构班级，可切换学生身份，试用发布考试、提交、成绩分析和错题复习。

演示空间和正式教师空间按后端权限隔离。演示入口有限流，请勿向演示班级录入真实学生资料。

## 设置唯一的 Master 管理账户

首次设置 Master 账户需要 **应用的设置密钥 SETUP_KEY**。它与 Cloudflare API Token 不同。

1. 在 Cloudflare 控制台进入 Workers & Pages → 本应用 → Settings → Variables and Secrets。
2. 添加类型为 Secret 的 `SETUP_KEY`。自行设置至少 24 个字符的私密随机内容，保存并部署。此值只由老师保管，不发给学生，不写入聊天。
3. 回到应用，点击「首次使用 · 设置 Master 账户」，填写同一个设置密钥、自己设置的 Master 密码、确认密码和首个班级。管理账号固定为 `master`，无需填写教师姓名或邮箱。
4. 后续点击「Master 管理」，用固定账号 `master` 和自己设置的密码登录。由你统一维护所有项目和班级、添加学生、录入课程场景词汇、发布考试并私下分发每人的学习入口。学生开通账号后，学习码即失效，成绩与错题持续保存在同一个学生 ID 下。

公开部署在未配置 `SETUP_KEY` 时拒绝建立 Master 账户，不能由任意访问者抢先开通。数据库限制只能有一个正式管理账户。

已有版本如果已经建立过教师账户，不需重新初始化：使用 `master` 和原密码登录即可。原管理记录 ID 和所属班级、学生、词库、考试、成绩、错题全部保留；邮箱不再作为管理登录名。演示空间仍是虚构数据，与正式管理数据隔离。

正式使用时，把本机 `cloudflare/wrangler.deploy.json` 的 `vars.ALLOW_DEMO` 改为字符串 `"false"`，再执行 `npm run cf:deploy`，关闭新建演示空间。控制台修改变量后，也应同步自己的部署配置，以免下次发布覆盖变量设置。Workers 的 Secret 由平台保管，不写入配置文件。

## 本地开发

```sh
npm run cf:migrate:local
npm run cf:dev
```

两个命令都使用共享配置和本地 D1，默认保存在 `.wrangler` 中，不操作线上数据。可给两个命令传入相同的 `--persist-to` 路径以选择另一个本地数据库目录。

在本云环境中，Wrangler 的默认全局目录不可写。运行命令时设置 `XDG_CONFIG_HOME=/workspace/vocabulary/.wrangler/cli-config`，并关闭非必要遥测 `WRANGLER_SEND_METRICS=false`。这两项用于 CLI 的本地配置，不更改网络代理或 TLS 验证。

如需本地验证正式注册，在已忽略的 `cloudflare/.dev.vars` 中自行配置一个仅供本地使用的 `SETUP_KEY`。不要用线上密钥代替，也不要提交文件。

## 数据和边界

- Cloudflare 使用独立 D1 数据库；已有 Node 版 SQLite 数据不会自动导入。新试用没有迁移真实学生资料。
- Workers 密码使用带独立随机盐的 PBKDF2-SHA256（100000 次）；Node 版使用 scrypt。两种存储不能直接混用，导入旧账号需另行设计密码重置流程。
- 自动保存、提交时限、任务受众和批改都在后端执行。并发提交在 D1 原子批次中通过唯一令牌锁定，避免重复成绩和重复错题计数；并发开始只建立一份答题记录。
- 定时任务每 5 分钟处理一批逾期答卷，查看任务、名单、成绩或错题时也会处理对应账号范围内的逾期答卷。关闭浏览器不会取消考试时限。大量同时逾期的答卷可能分批出现在成绩页面。
- 浏览器纠错属性已关闭，但网页不能强制关闭系统或第三方输入法功能；考试前仍需设置学生电脑输入法。
- 朗读只使用电脑上已安装的本地英文语音；未安装时应用提示安装，不调用国外语音服务。
- 免费额度以 Cloudflare 当前控制台为准。请求数、数据库读写和执行时间都有上限，达到限制可能影响保存和提交；先用一个班级试运行并观察用量。
- 定期从 Cloudflare 导出 D1 数据并妥善保存。Node 版 `npm run backup` 只用于 Node 版 SQLite，不能用于 D1。

## 本次验证范围

在本地 workerd + D1 运行环境中，用现有浏览器流程验证了班级、学生账号、考试链接、定向发布、未来考试等待、自动保存与恢复、评分、教师成绩、错题复习及窄屏布局；整个浏览器流程禁止了所有第三方域名请求。

已在公开 HTTPS 地址通过 curl 验证 D1 真实数据读写、学生开通与登录、指定个人的考试、拒绝未分配学生、保存与恢复、5 次并发提交只批改一次（75 分）、教师查看姓名与成绩，以及错题复习保存。线上正式教师注册在尚未设置 SETUP_KEY 时正确返回拒绝注册提示。

本次环境的 Python urllib 请求该公开域名返回 403/1010，而 curl 可以访问。公开页面在此环境的 Chromium 中遇到代理 CA 信任错误，因此没有宣称完成公开页面的浏览器验证；没有关闭 TLS 校验来绕过。Windows/macOS 真机、学校网络和中国大陆免 VPN 可用性需要实际试用。
